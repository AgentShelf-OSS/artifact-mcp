# Artifact MCP v1.18.0

## Viewer geolocation

Artifacts can ask the viewer shell for the viewer's current position, one fix at a time.

- The artifact frame sends `geo:hello` and receives `geo:ready { supported, remembered }`.
- `geo:request { requestId, highAccuracy? }` returns `geo:position { requestId, lat, lon,
  accuracy, timestamp }` or `geo:error { requestId, reason }`.
- Before the browser prompt, the shell asks its own question for each artifact: "Don't allow",
  "Allow once" or "Always allow here". The browser permission covers the whole artifact origin,
  so this second question keeps one artifact's grant from applying to every other artifact.
  "Always" is kept in the viewer's browser storage and is removed if the browser denies access.
  `geo:forget` clears it.
- One request runs at a time, with at least two seconds between lookups. Historical views,
  raw documents and public shares have no geolocation capability.
- The iframe sandbox, CSP and response headers are unchanged. The position is not sent to the
  server by the shell.

See `docs/adr/0016-viewer-geolocation-via-shell-consent.md`.

## Schema and configuration

No schema change (40). No new configuration.

## Deployment and rollback

The change is limited to the viewer shell script. To roll back, restore the v1.17.0 binary.
Stored "Always allow here" choices stay in viewers' browsers and are ignored by v1.17.0.
