# Artifact MCP v1.11.0

## Library organization

Organization-owned folders reference existing artifacts. An artifact can belong to several
folders. Deleting a folder preserves its artifacts. Folder creators and administrators can
curate membership; other organization members can browse readable contents.

Reel Shelf, Contact Sheets, and Gallery Ribbons share the existing search, category,
organization, status, and artifact controls. View, preview size, ribbon order, and collapse
preferences belong to each viewer. Folder membership does not grant artifact access.

## Schema and compatibility

Schema advances from 36 to 37. Upgrades from the previous public release at schema 34 also
apply the existing ordered migrations 35 and 36 before migration 37. Both runtimes use the
same collection migration. Startup applies migrations automatically.

Migration 37 adds collection, membership, and viewer preference tables and supporting
indexes. Membership changes and their audit records commit in one transaction. Moving an
artifact to another organization removes incompatible memberships and covers.

This release retains the revision-pinned viewer capture and operator-configured fixed live
actions from the native runtime. These optional features require explicit operator
configuration. Collection views need no new environment settings or external service.

## Deployment and rollback

Verify the published checksums, manifest, and attestations. Capture and test a backup of the
database, artifact bodies, previews, and configuration. Record the running binary before
replacement. After deployment, check health, schema 37, authenticated library reads, and a
folder create/update/delete operation.

Migration 37 is additive. A previously deployed schema-36 binary can run against the
database while ignoring the new tables. Preserve the database during a binary rollback so
that artifacts published after deployment remain available. A rollback to an older public
release also needs a compatibility review of migrations 35 and 36. Do not restore a full
database backup over later artifact writes.

## Validation

The collection implementation passed Node and Rust unit/integration tests, cross-runtime
HTTP conformance, and browser checks for membership permissions, persistence, responsive
layout, and all three presentations. Release CI validates the combined source before
publication. The release workflow checks the exact image against historical fixtures.
