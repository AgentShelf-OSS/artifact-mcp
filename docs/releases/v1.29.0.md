# Artifact MCP v1.29.0

This release restricts the credentials that a managed connection can reference, lets
administrators choose those credentials from a list, and stops the ETag middleware from holding
streamed responses.

## Schema

Schema 40 before and after. No schema migration.

## Changes

| Area | Change |
| --- | --- |
| Managed connections | A managed connection may reference only environment variables named `ARTIFACT_DATA_CREDENTIAL_<NAME>` (PR #120). `<NAME>` uses uppercase letters, digits and underscores. A managed connection also cannot set `Host`, `Cookie`, `Connection`, `Content-Length` or `Transfer-Encoding` from a reference. Saving a connection that breaks either rule returns `credential_reference_not_allowed` (400). |
| Connection editor | The credential field is a list of the `ARTIFACT_DATA_CREDENTIAL_` variables that the server process has (PR #121). A saved reference that the server lacks stays selected and is marked "(unavailable)". |
| Administration API | `GET /settings/data-sources` also returns `credential_variables`: the sorted names of the `ARTIFACT_DATA_CREDENTIAL_` variables in the server environment. Values are never read into the response. |
| HTTP | The ETag middleware passes through any body without an exact size (PR #119). NDJSON data operations and the Listen PCM stream now send their headers and first bytes at once, instead of after the upstream finishes. Buffered HTML, JSON, raw artifact and error responses keep their ETags and conditional-GET handling. |

## Why the prefix rule exists

A managed connection chooses its upstream host. Before this release, an administrator could save
a connection to a host they control, reference any process variable (for example a bot token or
an encryption key), and press **Test connection** to receive its value. The missing-reference
list also showed which variables exist. The prefix rule limits managed connections to variables
that the operator named for that use.

Every administrator can still send the value of any `ARTIFACT_DATA_CREDENTIAL_` variable to a
host they choose. Give that prefix only to credentials that administrators may use.

## Configuration and compatibility

- No new settings. Credentials for managed connections must use the `ARTIFACT_DATA_CREDENTIAL_`
  prefix.
- Operator sources in `ARTIFACT_DATA_SOURCES_FILE` do not change. They may still reference any
  variable, and their startup validation is unchanged.
- Artifact data bindings refer to source ids, not to variable names. No artifact needs a change.
- A managed connection saved before this release with a reference outside the prefix, or with a
  reserved header, still loads. Startup does not fail. That connection reports `config_error`,
  lists the reference as missing even when the variable is set, and makes no requests. Startup
  logs this warning once for each such connection, with its `source_id`:
  `managed data source references a credential outside ARTIFACT_DATA_CREDENTIAL_; it reports config_error until its references are renamed`.
- To repair such a connection, set the value under an `ARTIFACT_DATA_CREDENTIAL_` name in
  deployment configuration, restart the server, and choose the new name in the connection
  editor.
- The editor lists only variables the server has. To stage a connection before its variable is
  deployed, create it through the administration API.
- Streamed responses (`application/x-ndjson`, `application/vnd.artifact.pcm`,
  `text/event-stream`) do not have an `ETag` header. Server-sent events had none before this release either.
- MCP surface: no change. `serverInfo.version` reports `1.29.0`.
- Conformance: `connections.lifecycle` has a new step that rejects a reference to `PATH` with
  `credential_reference_not_allowed`. Its missing-reference step now uses a prefixed name.

## Deployment and rollback

No migration. Install the release binary as usual. The `artifact-preview` renderer has no
changes.

Before the upgrade, check the managed connections in **Settings → Connections**, or in
`GET /settings/data-sources`. Each `headers_env` value must start with
`ARTIFACT_DATA_CREDENTIAL_`. Rename the others first, or plan to repair them after the upgrade as
described above. A deployment with no managed connections needs no action.

Rollback: the v1.28.1 binary starts on data written by this release (schema 40). After a
rollback the prefix rule and the credential list are gone. Connections that use prefixed names
continue to work.

## Verification

- New tests: a streaming test holds NDJSON, PCM and SSE responses open after one chunk and
  requires the headers and first chunk within two seconds, with no ETag. Data tests cover the
  prefix rule, the reserved headers, a stored reference outside the prefix that is never sent,
  and the credential name list. A browser test saves a connection through the credential list
  and checks the "(unavailable)" marking.
- CI passed on the merge commit of each PR.

## Vulnerability exceptions

None.
