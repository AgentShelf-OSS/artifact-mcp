# Artifact MCP v1.7.0

## Schema

- The public v1.6.1 release upgrades from schema 23 to schema 31.
- The VM310 PBI-079 production baseline upgrades from schema 29 to schema 31.
- Migrations are forward-only and run before the listener becomes ready. Frozen historical
  fixtures cover every boundary through schema 31, reopen idempotency, corruption refusal, and
  tenant isolation.

## Operator steps

1. Verify the backup identity above and its `SHA256SUMS` before promotion.
2. Verify `WEBHOOK_ENC_KEY` and `AUDIT_LEDGER_HMAC_KEY` are present without printing or sourcing
   either value. `WEBHOOK_ENC_KEY` must remain a canonical base64-encoded 32-byte key.
3. Keep `DISCORD_INBOUND_ENABLED` absent or set to `0` for the initial rollout.
4. Deploy only the immutable OCI reference from `release-manifest.json`; do not deploy a mutable
   tag or rebuild on VM310.
5. Wait for `/health` to return `{"status":"ok"}` and verify that the database reports schema 31.
6. Confirm Settings returns only redacted organization Discord readiness and that browser token
   fields remain empty after save and reload.
7. Confirm Artifact MCP feedback, publishing, and viewing remain available with Discord
   unavailable. Do not enable historical recovery unless one exact selected-webhook notification
   can be matched to the canonical artifact URL.
8. Enable inbound synchronization only in a later, explicit canary after the Discord application
   has the required gateway intents and least-privilege channel permissions.

## Configuration changes

- Discord bot credentials are per organization, write-only in the browser, encrypted at rest, and
  never returned by an API.
- `DISCORD_BOT_TOKEN` is migration fallback only. Do not display, log, copy into release evidence,
  or treat it as the ongoing organization credential.
- Organization settings control the default outbound-threading policy. Artifacts can explicitly
  keep discussion in Artifact MCP or inherit that organization default; guarded two-way sync
  additionally requires the organization credential and readiness boundary.
- Historical recovery is bound to the exact selected notification webhook identity and canonical
  artifact URL. Missing, incomplete, or redacted history fails closed without creating duplicate
  notification floods. When several exact cards exist, recovery selects Discord's newest match.
- Artifact MCP remains canonical during Discord REST, Gateway, permission, rate-limit, and thread
  failures.

## Compatibility and rollback

- Current MCP legacy-client behavior from v1.6.1 is retained alongside the newer MCP contract.
- The Node comparison runtime intentionally exposes a safe-unavailable projection for the
  Rust-owned organization credential and inbound Gateway capabilities.
- An image-only rollback is unsafe after schema 31 has been opened. Roll back by stopping the
  candidate, restoring both data and deployment configuration from the immutable backup above,
  and starting the previously verified immutable rollback image recorded in the release manifest.
- Leave inbound synchronization disabled throughout rollback.
