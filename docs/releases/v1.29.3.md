# Artifact MCP v1.29.3

This is a security maintenance release. It updates the dependencies that had RustSec advisories
(PR #128), adds a dependency policy check to CI (PR #130), and finishes the refactor follow-ups
(PR #131). Behaviour, settings, the MCP surface and the schema do not change.

## Schema

Schema 40 before and after. No schema migration.

## Security fixes

| Crate | Change | Advisories |
| --- | --- | --- |
| rustls | 0.23.42 → 0.23.46 | RUSTSEC-2026-0285, -0346, -0348, -0349 |
| rustls-webpki | 0.103.13 → 0.103.16 | RUSTSEC-2026-0382 |
| webpki-root-certs | 1.0.9 → 1.0.10 | RUSTSEC-2026-0383 |
| tokio | 1.53.1 → 1.53.3 (server and preview renderer) | RUSTSEC-2026-0386 |
| zstd-sys | 2.0.16 → 2.1.2 | RUSTSEC-2026-0410 |
| quinn-proto | 0.11.16 → 0.11.18 | RUSTSEC-2026-0338 to -0342 (not compiled for the shipped targets) |
| chacha20 | 0.10.1 → 0.10.2 | yanked release |

rustls is the TLS client for all outbound traffic: webhooks, data sources, the JWKS key fetch and
the Discord gateway. rustls 0.23.46 needs aws-lc-rs 1.18, so aws-lc-rs moves 1.17.3 → 1.18.2 and
aws-lc-sys 0.43.0 → 0.46.0. Newer releases of those two were held back because they were less
than 7 days old.

## Changes

| Area | Change |
| --- | --- |
| Dependency policy | A `Dependencies` workflow runs cargo-deny on every change and daily. It checks advisories, licences, wildcard versions and crate sources for all three Cargo workspaces. Exceptions and their reasons live in `deny.toml`. |
| Supply chain | Every GitHub Action is pinned to a commit SHA. Dependabot proposes cargo and action updates after a 7-day cooldown (30 days for major versions). |
| Documentation | Rustdoc warnings fail CI. Broken and private intra-doc links are fixed. |
| Build | The deterministic test fakes (`FixedClock`, `SequentialIdSource`, `SeededRandom`, `ScriptedRandom`, `Testkit`) compile only for tests (`test-util` feature). The release binary no longer contains them. |
| Discord gateway | `discord_gateway_runtime/runtime.rs` is split into `metrics.rs` and `normalize.rs`. The event fingerprint (the deduplication key) is pinned by golden tests and does not change. |
| Tests | Four characterization tests that could not fail are strengthened. |

## Configuration and compatibility

- No new, changed or removed settings.
- MCP surface: no change. `serverInfo.version` reports `1.29.3`.
- Log events from the moved gateway code have a new `target`
  (`artifact_mcp::integrations::discord_gateway_runtime::metrics` or `::normalize`). Messages and
  levels do not change.

## Deployment and rollback

No migration. Install the release binary as usual. The `artifact-preview` renderer gets the tokio
update.

Rollback: the v1.29.2 binary starts on data written by this release (schema 40).

## Verification

- `cargo fmt`, `cargo clippy -D warnings` (with and without features), 2,550 tests, doctests,
  strict `cargo doc` for all three workspaces, `cargo xtask historical-fixture
  --verify-against-committed` and `cargo deny check` passed. CI passed on each merge.
- A differential rehearsal ran the live v1.29.2 binary and this source on separate copies of a
  production backup (371 artifacts, 1,261 revisions, schema 40):
  - 9,116 read requests: 0 differences after masking timestamps and nonces.
  - The write phase and the admin steps: equal outputs and equal database fingerprints.
  - Equal warning logs.
  - Restart, `backup`, `verify-backup`, rollback to v1.29.2 and boot from the new backup: all
    passed.
  - It did not cover outbound TLS against real endpoints, the preview renderer or the Discord
    gateway. CI's JWKS HTTPS transport tests run the rustls client against a local TLS server.

## Vulnerability exceptions

These advisories remain in the dependency tree. Each is listed in `deny.toml` with its reason.

| Advisory | Crate | Why it is accepted |
| --- | --- | --- |
| RUSTSEC-2023-0071 | rsa 0.9 | Marvin timing attack on RSA private-key operations. The server only verifies JWT signatures with public keys. No fixed release exists. |
| RUSTSEC-2026-0387 | crypto-bigint 0.5 | Timing variability, reached through p256 0.13 (Web Push VAPID signing and ECDH). The fix needs the p256 0.14 / jsonwebtoken 11 upgrade, planned separately. |
| RUSTSEC-2026-0398, -0403 | zstd-safe 7 | Affect the `seekable` and `legacy` features, which are not compiled. twilight-gateway 0.17 does not accept zstd-safe 8. |
| RUSTSEC-2026-0374 | basic-toml | Unmaintained. Used only at build time by the askama template macro. |
