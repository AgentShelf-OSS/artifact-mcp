# Artifact MCP v1.14.0

## Character voices in Listen

Before this release, Listen read every block with the one voice selected in the player. Stories with
several narrators or speakers sounded like a single reader.

- An artifact can declare a cast of voice roles in
  `<script type="application/json" id="artifact-reader-cast">` and tag blocks or inline elements
  with `data-artifact-reader-voice`. See [Voice roles](../readable-artifacts.md#voice-roles) and
  [ADR 0014](../adr/0014-listen-voice-roles-declared-by-artifacts.md).
- When a cast is present, the expanded player shows a **Voices** section before playback starts:
  one voice picker per role, a Preview button, and a **Character voices** switch. The artifact's
  suggested voices are the defaults when available; otherwise distinct available voices are
  assigned. The default role follows the main voice. Choices persist per artifact in the
  browser's reader preferences.
- An inline role splits a paragraph into spoken segments, so dialogue can use a different voice.
  Word and passage highlighting stay within the current segment, and pronunciation hints still
  apply.
- The compact player shows the current role and voice.
- Ereaders can provide a spoken chapter heading with `data-artifact-reader-summary` on the
  chapter heading and short intros with `[data-artifact-reader-intro]`. The heading's metadata
  line is no longer read when a summary is present.
- Prefetch follows the next block's voice engine, so a change from a WAV voice to a streaming
  voice does not request the same paragraph twice.

The artifact only declares roles and suggests voices. It cannot select a voice, send reading
instructions, or learn the listener's choices. Artifacts without a valid cast behave as before.
Saved positions in artifacts that add roles fail their fingerprint check once and restart cleanly.

A new reader regression, `reader-voice-cast`, runs against both the Node and Rust runtimes.

## Schema and configuration

The schema remains 39. There are no database migrations, new environment variables, or speech
worker changes. The change is limited to the viewer shell and the injected reader scripts.

## Deployment and rollback

Verify the release checksums, manifest, and attestations before installation. Keep the current
v1.13.1 binary and deployment record for rollback. A rollback to v1.13.1 uses the same schema and
only removes the Voices section; role attributes in artifacts are then ignored.
