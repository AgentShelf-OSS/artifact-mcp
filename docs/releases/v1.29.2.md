# Artifact MCP v1.29.2

This release changes the internal structure of the server only. It completes the source split
begun in v1.28.1: the delivery worker, the discussion store, the security audit ledger (PR #125)
and the remaining large persistence, HTTP, rendering and integration modules (PR #126) move into
smaller modules. Behaviour, settings, the MCP surface and the schema do not change.

## Schema

Schema 40 before and after. No schema migration.

## Changes

| Area | Change |
| --- | --- |
| Delivery | `integrations/delivery_worker` is a module directory. Event delivery runs as named stages. |
| Discussions | `persistence/discussions` is a module directory. The SQL text does not change. |
| Security audit | `security/audit` is a module directory. The canonical encoding, the HMAC chain and the verification results do not change. Golden digest tests pin them. |
| Persistence | `orgs`, `discord_inbound`, `outbox`, `discord_organization`, `push`, `webhooks`, `keys` and `feedback` are module directories. |
| HTTP | `http/ingress`, `routes/admin`, `routes/speech` and `routes/mcp` are module directories. Ingress admission runs as named steps in the same order. |
| Rendering and integrations | `render/portal`, `integrations/thumbnails`, `discord_discussion`, `discord_gateway_runtime`, `push_runtime` and `artifacts/reconciliation` are module directories. Rendered HTML is byte-identical. |
| Long functions | No function over 100 lines remains outside the append-only migration bodies. |

## Configuration and compatibility

- No new, changed or removed settings.
- MCP surface: no change. `serverInfo.version` reports `1.29.2`.
- Log events from moved code have a new `target`, one level deeper in the module path. For example,
  `durable webhook outcome could not be recorded` now comes from
  `artifact_mcp::integrations::delivery_worker::outcome`. Messages and levels do not change.
  `RUST_LOG` directives match module-path prefixes, so a filter such as
  `artifact_mcp::persistence::outbox=debug` still matches. Only filters that compare the exact
  target string need an update.

## Deployment and rollback

No migration. Install the release binary as usual. The `artifact-preview` renderer has no
changes.

Rollback: the v1.29.1 binary starts on data written by this release (schema 40).

## Verification

- New characterization tests pin the order of checks, writes and awaits before each move. Examples:
  delivery outcome order and backoff, audit chain digests and tamper rejection, ingress admission
  order, speech time to first byte, and portal HTML bytes.
- `cargo fmt`, `cargo clippy -D warnings`, 1268 tests, doctests and
  `cargo xtask historical-fixture --verify-against-committed` (42/42) passed. CI passed on both
  merge commits.
- A differential rehearsal ran the live v1.29.1 binary and this source on separate copies of a
  production backup (367 artifacts, 1,248 revisions, schema 40):
  - 9,023 read requests: 0 differences after masking timestamps and nonces.
  - The write phase and 33 admin steps: equal outputs and equal database fingerprints.
  - Equal warning logs.
  - Restart, `backup`, `verify-backup`, rollback to v1.29.1 and boot from the new backup: all
    passed.
  - It did not cover the preview renderer, the Discord gateway or outbound network delivery.
