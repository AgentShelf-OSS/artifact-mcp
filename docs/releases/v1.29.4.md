# Artifact MCP v1.29.4

This is a maintenance release. It updates minor and patch dependencies (PRs #133 and #137),
embeds the dependency list in the server binary (PR #140), separates the release job from
dependency code (PR #139), and splits the viewer shell script into parts (PR #146). Behaviour,
settings, the MCP surface and the schema do not change.

## Schema

Schema 40 before and after. No schema migration.

## Changes

| Area | Change |
| --- | --- |
| Supply chain | The server binary is built with `cargo auditable`, which embeds the resolved dependency list in a `.dep-v0` section. The image SBOM and the vulnerability scan now see the Rust crates inside the static binary. |
| Release workflow | The release job that holds signing and attestation credentials no longer runs dependency code; the build runs in a separate job. |
| Viewer shell | `assets/shell.js` is split into 19 ordered parts under `assets/shell/`, joined at compile time. The served script is byte-identical (sha256 `68aa4302…`). |
| Tests | JWT verification (ES256, EdDSA, RS256, PS256) and the VAPID signature are pinned by vectors ahead of the planned RustCrypto upgrade. |
| CI | GitHub Actions bumped and pinned by commit SHA. |
| Documentation | The CT222 runbook keeps the Chrome sandbox, the renderer token and the 640M memory limit when the unit is folded. PR Watch examples include the `attention` operation. |

## Configuration and compatibility

- No new, changed or removed settings.
- MCP surface: no change. `serverInfo.version` reports `1.29.4`.
- Artifact IDs keep their format; `nanoid` 0.5 changes only the random source.

## Deployment and rollback

No migration. Install the release binary as usual. Install the `artifact-preview` asset on CT222
too: CT222 still runs the v1.28.0 renderer (tokio 1.53.1), so this also brings it the tokio
updates from v1.29.3 (RUSTSEC-2026-0386) and this release.

Rollback: the v1.29.3 binary starts on data written by this release (schema 40). The renderer
rolls back by restoring the previous `/usr/local/bin/artifact-preview`.

## Verification

- CI passed on each merge: `cargo fmt`, `cargo clippy -D warnings`, all three workspaces' tests,
  doctests, strict `cargo doc`, `cargo xtask historical-fixture --verify-against-committed`,
  `cargo deny check` and the browser suites.
- A differential rehearsal ran the live v1.29.3 binary and this source on separate copies of a
  production backup (383 artifacts, 1,284 revisions, schema 40):
  - 9,386 read requests: 1 difference, the expected `serverInfo.version` (`1.29.3` → `1.29.4`).
  - The write phase and the 33 admin steps: equal outputs and equal database fingerprints.
  - Equal warning logs.
  - Restart, `backup`, `verify-backup`, rollback to v1.29.3 and boot from the new backup: all
    passed.
  - It did not cover outbound TLS against real endpoints, the preview renderer or the Discord
    gateway.

## Vulnerability exceptions

Unchanged from v1.29.3. RUSTSEC-2023-0071 (rsa) and RUSTSEC-2026-0387 (crypto-bigint 0.5) are
removed by the RustCrypto upgrade in draft PR #145, planned for the next release.
