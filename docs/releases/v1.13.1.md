# Artifact MCP v1.13.1

## Install an artifact as its own app

Before this release, every installed app used the single site manifest with start URL `/`, so a
Home Screen icon added from an artifact page always opened the library.

- The artifact viewer page now links a per-artifact manifest, `GET /{id}/manifest.webmanifest`.
  An app installed from an artifact page opens that artifact (`id`, `start_url`, and `scope` are
  `/{id}`) and uses the artifact title as its name (at most 60 characters) and short name (at most
  12 characters). It keeps the site icons, colors, and standalone display.
- The viewer page also sets the iOS Home Screen title (`apple-mobile-web-app-title`) to the
  artifact title. On iPhone and iPad, open the artifact page in Safari and use
  **Share → Add to Home Screen**.
- The library page now links the site manifest, so an app installed from the library is the
  general "Artifacts" app.
- The per-artifact manifest has the same access as the viewer page: a signed-in viewer of the
  artifact's organization, or an administrator. Other requests get the concealed `404`. Public
  shares get no per-artifact manifest. Do not add `/{id}/manifest.webmanifest` to a Cloudflare
  Access bypass; it names a private artifact.

Node and Rust emit byte-identical manifests (compact JSON, sorted keys). A new conformance case,
`web-push.artifact-manifest`, compares them.

## Schema and configuration

The schema remains 39. There are no database migrations or new environment variables.

## Deployment and rollback

Verify the release checksums, manifest, and attestations before installation. Keep the current
v1.13.0 binary and deployment record for rollback. A rollback to v1.13.0 uses the same schema.
Apps already installed from an artifact page under v1.13.0 still open the library; reinstall them
from the artifact page to get the per-artifact app.
