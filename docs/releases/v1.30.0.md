# Artifact MCP v1.30.0

This release refreshes the web UI (PR #151, which includes the information architecture pass from
PR #152) and moves the crypto dependencies to the current RustCrypto generation (PR #145). That
upgrade retires the last two accepted advisories. It also splits the gallery script and two Discord
modules into smaller files (PRs #149 and #150) and aligns the docs with the Rust-only codebase
(PR #147). The MCP surface and the schema do not change.

## Schema

Schema 40 before and after. No schema migration.

## Changes

| Area | Change |
| --- | --- |
| Gallery | One View menu holds folder display, Grid or List, and preview size, so the toolbar fits on one row. The whole card opens the artifact; the Open button is gone. Favorite, Share and More stay on the card, and Download and Hide or Show moved into More. The toolbar shows New folder only when the shelf's New folder tile is off-screen. Hidden artifacts carry a "Hidden" tag. |
| Look | A warm paper and brass palette in light and dark. Interface text uses one sans family at 12px or larger; page, folder and card titles use Fraunces; monospace is kept for identifiers and code. Brass marks the primary action in each form and dialog, and stroke icons replace text glyphs. With no saved theme, the gallery follows the operating-system dark setting. |
| Other pages | The viewer bar, administration, folder dialogs, not-found, sign-in and access-retry pages use the same tokens. Phones keep 44px targets and do not scroll sideways at 320px. |
| Font route | `GET /fonts/fraunces-v1.woff2` serves the embedded Fraunces face (SIL OFL 1.1, licence in `assets/licenses/fraunces-OFL.txt`) with immutable caching. Like `/icons/{name}`, any other name gets the concealed 404. |
| Crypto | p256 0.14 (VAPID signing, ECDH), hmac 0.13 and sha2 0.11, hkdf 0.13, aes-gcm 0.11 (webhook URL encryption, Web Push). jsonwebtoken 11 uses its `aws_lc_rs` backend. Stored webhook ciphertext, VAPID keys and the audit chain keep their formats. |
| Code layout | `assets/portal.js` is split into ordered parts under `assets/portal/`, joined at compile time. The Discord inbound and discussion request modules are split into submodules. Both are moves with no behaviour change. |
| Documentation | Contributor and operator docs describe the Rust-only codebase. The screenshot gallery, the frontend guide and `docs/design/ui-refresh-2026-11.md` describe the new UI. |

The preview renderer has no changes. CT222 keeps the v1.29.4 `artifact-preview`.

## Configuration and compatibility

- No new, changed or removed settings.
- MCP surface: no change. `serverInfo.version` reports `1.30.0`.
- Identity: with the aws-lc backend, an RSA key under 2048 bits in an issuer's JWKS is rejected.
  The previous backend had no practical minimum. The production Cloudflare Access issuer serves
  2048-bit RS256 keys.
- Theme: a user who never chose a theme now sees the dark theme when the operating system is
  dark.

## Deployment and rollback

No migration. Install the release binary as usual. No CT222 change.

Rollback: the v1.29.4 binary starts on data written by this release (schema 40). Webhook URLs
encrypted by either version decrypt with the other.

## Verification

- CI passed on each merge: `cargo fmt`, `cargo clippy -D warnings`, all three workspaces' tests,
  doctests, strict `cargo doc`, `cargo xtask historical-fixture --verify-against-committed`,
  `cargo deny check` with both advisory ignores removed, and the browser suites.
- Crypto characterization tests pass unchanged: the JWT vectors (ES256, EdDSA, RS256, PS256), the
  pinned RFC 6979 VAPID JWT, the RFC 8291 section 5 vector, the webhook-cipher pinned records, the
  SHA-256 key-hash vectors, the audit-chain HMAC goldens and the historical fixtures.
- Before merging #145, webhook ciphertext round-tripped between the old and new code in both
  directions with the production key, and both derived the same VAPID public key.
- The `assets/portal.js` split produced byte-identical script output before the UI refresh
  changed it.
- Before release, a tool built from this release's source ran against a read-only copy of the
  production database (schema 40) with the production keys:
  - Every stored ciphertext decrypted: 1 of 1 webhook URLs and 2 of 2 Web Push endpoints, with
    0 failures.
  - One test Web Push to each of the 2 subscriptions, with a VAPID JWT and an aes128gcm body from
    the new code: both returned `201 Created`.
  - The Cloudflare Access JWKS serves two 2048-bit RS256 keys, which the aws-lc backend accepts.
  - A real Cloudflare Access JWT can only be verified once the release runs in production.

## Vulnerability exceptions

RUSTSEC-2023-0071 (rsa) and RUSTSEC-2026-0387 (crypto-bigint 0.5) are removed from `deny.toml`.
Neither crate is in the dependency graph. The other exceptions (basic-toml at build time, and two
zstd-safe advisories behind features that are off) are unchanged.
