# Artifact MCP v1.20.0

## Native host bridge (ADR-0018, Phase 1)

When the Artifact MCP Android app (`AgentShelf-OSS/artifact-mcp-android`) hosts the viewer, the
shell relays consented native capabilities between the artifact and the app. In a browser nothing
changes: artifacts that ask receive `native:ready {available:false}`.

- The shell finds the app through an origin-scoped `ArtifactNative` WebView message channel. The
  artifact iframe keeps its sandbox and never receives the channel.
- Artifact messages: `native:hello`, `geo:watch` / `geo:unwatch` (background location with a
  foreground-service notification), `audio:queue`, `audio:geotrigger` (the app plays an item the
  first time the device comes within its radius, even with the screen off), `audio:stop` and
  `notify:show`. Replies: `native:ready`, `geo:position`, `geo:error`, `audio:state`,
  `audio:played` and `native:error`.
- Background location and notifications each ask a per-artifact question in the shell, stored
  like ADR-0016 consent. A host denial clears the stored consent.
- Items are validated in the shell: ids, titles, text up to 1500 characters, same-origin audio
  URLs only, coordinates, a radius of 500–10000 m, and at most 50 trigger items.
- Played events wait until the artifact says `native:hello`, and are then delivered and
  acknowledged to the app.

## Schema and configuration

No schema change (40). No new configuration.

## Deployment and rollback

Shell script change only. To roll back, restore the v1.19.0 binary. Stored native consents stay in
viewers' browser storage and are ignored by v1.19.0.
