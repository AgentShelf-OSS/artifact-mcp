# Artifact MCP v1.9.0

## Release highlights

- Pocket narration follows the spoken word. Selected passages remain highlighted while audio prepares; pause retains the current word and Stop clears it. Unsupported timing or browser capabilities fall back to passage highlighting.
- Replay sentence in the expanded player reuses the current Pocket audio without another synthesis request. It adds no persistent cache. Current decoded audio is bounded to 8 MiB per chunk and released on Stop, page exit, or moving to another chunk.
- Playback speed changes preserve pitch. Interrupted streams retry twice from the last played position; Pause and Stop cancel recovery.
- The optional Pocket worker supports int8 quantization and a pinned timestamp-enabled runtime. Sentence-aware chunking and next-chunk prefetch retain authored sentence boundaries where possible.
- Includes the unreleased v1.8.0 native Listen player, 21 Pocket preset voices, inline Read from Here, reading scopes, supported ebook chapter continuation, sleep timers, saved positions, and organization/per-viewer state additions.
- RAVEN comparison code and measurements are included as an opt-in experiment. Its streaming noise remains unresolved; its viewer integration uses complete paragraph WAVs. It is not enabled by default. FrontPocket notes record the sentence-replay design exploration.

## Schema and compatibility

Schema remains 34 when upgrading from v1.8.0. No schema migration.

Upgrading from the previous published v1.7.2 release moves schema 32 to 34 through the existing state-storage migrations. Back up the database and artifact bodies before upgrading. Artifact HTML requires no changes.

Word highlighting and Replay sentence require the timestamp-capable Pocket worker. The updated server falls back to legacy PCM streaming when an older worker returns 404 or 415 for timed streaming. Browsers without the needed audio-worklet support use normal WAV playback for non-default speed. Sentence replay is unavailable when timing or the beginning of the current sentence is unavailable.

## Configuration and upgrade

1. Record the current binary or immutable image digest and back up database, artifact bodies, and configuration.
2. Deploy v1.9.0 and verify `/health`. Refresh open viewers to load the new player assets.
3. For Pocket narration, rebuild the worker using [Pocket setup](../../ops/pocket-tts/README.md). The timestamp fork is pinned to a source commit. Set `POCKET_TTS_QUANTIZE=1` to enable int8; changing it changes the worker audio-cache namespace.
4. Retain worker token-file authentication. The timed endpoint uses the existing viewer authorization, artifact access checks, and synthesis limits. No browser connects directly to a worker.
5. Speech remains optional. Existing installations without a worker continue to publish and view artifacts normally. See the [TTS operations guide](../../ops/tts/README.md).

RAVEN requires explicit `RAVEN_TTS_WORKER_URL` and token-file configuration. It should remain disabled unless deliberately testing the trial. SoundTouchJS is vendored with its license and source map; no third-party script host is required.

## Rollback

For a v1.8.0 installation already on schema 34, restore its recorded server binary/image and worker configuration. To disable narration, set `TTS_ENABLED=0`, clear `TTS_ARTIFACT_IDS`, and restart.

To return to v1.7.2/schema 32, stop the service and restore the matching pre-upgrade database, artifact bodies, and configuration before starting the recorded older binary/image. Do not run an older server against an unsupported schema.

## Validation and release process

The release workflow requires default-branch CI, builds and scans the candidate image, verifies historical fixtures, and publishes the binary, checksums, SBOMs, attestations, and migration notes. Browser testing of the narration changes also covered real Pocket playback, selection highlighting, replay without extra synthesis, pause/resume, speed changes, chapter continuation, and cleanup.

## Vulnerability exceptions

None declared. Release vulnerability scanning remains a publication gate.
