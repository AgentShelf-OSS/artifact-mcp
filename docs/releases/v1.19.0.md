# Artifact MCP v1.19.0

## Broker POST and streaming operations

Live-data operations (ADR-0009) gain two options. The iframe sandbox, CSP and the rule that only
operators and administrators choose upstream URLs and headers are unchanged.

- `"method": "POST"` sends the declared parameters as a typed JSON body. POST operations allow up to
  32 parameters and strings up to 16384 characters; the body may not exceed 64 KiB. GET operations
  keep their limits (16 parameters, 256 characters).
- `"stream": true` relays an upstream that answers newline-delimited JSON
  (`application/x-ndjson`). The viewer calls the new `POST /:id/data/stream` route and receives
  `{"chunk":…}` lines, then `{"done":true}` or one `{"error":…}` line. `timeout_ms` may be up to
  120000 for streaming operations; a 30-second gap between lines ends the stream. Calling
  `/data/query` on a streaming operation returns its last line.
- The shell posts `data:chunk` messages for each line and `data:result` with the last one. The
  injected SDK adds `window.artifact.data.stream(binding, operation, params, onChunk, { signal })`.
- `list_data_sources` and the administration views report `method` and `stream` for every
  operation. Managed sources accept the same fields.

See `docs/adr/0017-broker-post-and-streaming-operations.md` and "POST and streaming operations" in
`docs/live-data.md`.

## Schema and configuration

No schema change (40). No new configuration. Existing operator-file and managed sources keep
working; the new fields default to `GET` and `false`.

## Deployment and rollback

To roll back, restore the v1.18.0 binary. Sources that use `method` or `stream` must be removed
from the operator file first, because v1.18.0 rejects unknown operation fields at startup.
