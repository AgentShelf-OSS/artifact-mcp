# Artifact MCP v1.32.0

This release makes the repository easier for AI coding agents to change safely (PR #162). It came
out of a three-round agent-readiness review by Claude Opus and GPT Sol, who rated v1.31.0 at 7.3
and 7.2 out of 10 and this code at 7.6 and 8.4. Most of the change is guards, documentation and
internal structure. Two behaviour changes are listed below.

## Schema

Schema 40 before and after. No schema migration.

## Behaviour changes

| Area | Change |
| --- | --- |
| Admin data bindings | `GET /settings/data-bindings/{id}` and the response after a successful update no longer report a storage, registry or decode failure as `200 {"bindings":{}}`. They return the existing logged 502 `data_unavailable` response. An artifact lookup failure returns that 502 instead of 404. Absent, invalid and organization-mismatched bindings still return 200 with an empty object, so the editor can open and repair stale bindings. |
| MCP output schemas | `list_artifacts` items and the `read_artifact` result and file items declare every emitted field and reject undeclared ones (`additionalProperties: false`). Outputs are validated at runtime, so a server change that adds an undeclared field now fails its tests instead of shipping. The validator also accepts `type` given as a list (for example `["string", "null"]`). Argument validation is unchanged. |

## Internal changes

| Area | Change |
| --- | --- |
| Agent instructions | `AGENTS.md` lists the CI gate commands and the rules agents most often miss. `CLAUDE.md` imports it. `CONTEXT.md` corrections; `CONTRIBUTING.md` adds the missing CI gates and an "add an artifact metadata field" checklist. |
| Gates | `cargo xtask gate` (`--dry-run`, `--skip-browser`) runs the CI commands of all three workspaces and fails when browser prerequisites are missing. A unit test fails when it drifts from `.github/workflows/ci.yml`. |
| Repository guards | `tests/repo_guards.rs` fails when a documented repository path is missing or a `tests/native/*.rs` file is not registered. |
| Row mapping | One artifact row mapper reads columns by name (`src/persistence/artifact_rows.rs`). Feedback delivery uses it too; delivered payloads are unchanged. `ArtifactMeta::fixture` (behind `test-util`) shortens test literals. |
| MCP contract | The frozen tools/list contract lives in `src/mcp/frozen_tools.json` with the same canonical hash. Tests check the hash, property-order coverage and that every schema keyword is implemented or explicitly listed. `src/mcp/tool_defs.rs` documents how to change a frozen tool. |
| Data port | `get_bindings`, which hid errors, is removed; callers use `try_bindings`. |
| Tooling | `ARTIFACT_MCP_BIN` is the only name for the server-binary variable in tests. |

## Configuration and compatibility

- No new, changed or removed settings.
- MCP surface: no tool, argument or tools/list byte change. The advertised `outputSchema` for
  `list_artifacts` and `read_artifact` is stricter. `serverInfo.version` reports `1.32.0`.
- No dependency changes.

## Deployment and rollback

No migration. Install the release binary as usual. No CT222 change, because the preview renderer is
unchanged.
