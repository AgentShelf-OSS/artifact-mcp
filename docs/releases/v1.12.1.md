# Artifact MCP v1.12.1

## Web interface responsiveness

Gallery search reuses the current card order when the sort choice has not changed. It caches
sort metadata and avoids repeated visibility changes. Gallery state is saved after a short pause
and immediately when the page closes or opens an artifact.

The folder views reuse card and membership indexes. They avoid repeating unchanged card controls,
and the All artifacts view no longer builds an inactive Reel Shelf.

Saved comment positions update once per animation frame during scrolling and resizing. Startup
messages and explicit position requests remain immediate. An early message listener and a
parent-to-frame handshake preserve viewer startup when the artifact loads before the viewer.

Discussion connection status loads when Details first opens. A successful result is reused;
a failed request can be retried. Voice discovery waits for browser idle time, with a two-second
deadline. The Listen control reserves its space while discovery is pending.

Styles and scripts remain inside each page. The shared asset caching experiment is excluded
because an older rollback binary could not serve those asset URLs.

## Schema and configuration

The schema remains 38. There are no database migrations or new environment variables.
The organization folder tools, service-principal ownership, folder dialogs, and action grants
from v1.12.0 remain supported.

The gallery still renders the full artifact list. Very large libraries can still take time to
load and display. This release does not add pagination or promise lower production network latency.

## Deployment and rollback

Verify the release checksums, manifest, and attestations before installation. Capture and test
a backup of the current database, artifact bodies, previews, and configuration. Keep the current
v1.12.0 binary and deployment record for rollback.

After installation, check health, schema 38, authenticated artifact and folder reads, a temporary
write, the gallery views, and the artifact viewer. A rollback to v1.12.0 uses the same schema and
retains support for API-key and OAuth-owned folders. Preserve the current database when restoring
the prior binary. Never restore an older full database backup over later artifact writes.
