# Artifact MCP v1.31.0

This release restructures the server's module boundaries and error handling (PR #160). It came out
of a two-member architecture review, Claude Opus and GPT Sol. They rated v1.30.1 at 7.5 and 8.0
out of 10, and this code at 9.0 and 9.2. Most of the change is internal. Wire formats, HTTP
statuses and bodies, stored rows and audit receipts stay the same, except for the three behaviour
changes listed below.

## Schema

Schema 40 before and after. No schema migration.

## Behaviour changes

| Area | Change |
| --- | --- |
| MCP live-data tools | A `data_unavailable` failure now reports as an unavailable error, the same as the HTTP data routes, instead of as a validation error. |
| API key roles | A stored key whose role is not exactly `reader`, `author` or `collaborator` is rejected with 401. Before, such a key authenticated, and an admin-organization key with an unknown role skipped the role check. All production keys use one of the three roles. |
| Collections, test setup only | With the inert collections service that tests use when collections are unavailable, a malformed MCP cursor reports its validation error before "database unavailable". Production always runs the real store. |

## Internal changes

| Area | Change |
| --- | --- |
| Live data | `DataError` replaces string errors across the data port; HTTP and MCP map every variant explicitly. |
| Collections | A `CollectionService` port replaces `DataService::pool()`. The port has one add and one remove, both returning the membership diff, a required audit record and a `NewCollection` input. |
| Access policy | A closed `Role` type is parsed once at authentication. Publisher read, list-scope (`ListScope`) and publish rules live in `security::access`. |
| Errors | One `internal(operation, error)` constructor logs every internal failure with an operation name. Errors that used to be dropped silently are now logged. No implicit `AppError`→`DataError` conversion remains. |
| Lifecycle | Raw-metadata artifact methods are crate-private, so callers must hold an authorization grant. Tests reach them through a `test-util` trait. |
| Preview tasks | Task persistence runs off the async workers. Recovery tells a missing task folder from an unreadable one and reports corrupt task files. |
| Layering | Shared contract types moved to `model`. `tests/layering.rs` fails CI when a lower layer imports an upper one. Exceptions are listed in an allowlist that the test checks for stale entries. |
| Misc | `actions` moved under `integrations`, with `ActionError` and one shared HTTP client; the investigation allowlist is unchanged. Speech parsers moved to `config`. Long SQL strings became constants. The anchor bridge script moved to `assets/artifact-anchor-bridge.html`, byte-identical. Comments citing the removed JavaScript implementation were rewritten or removed, and ADR-0001 was amended for the Rust composition seam. |

## Configuration and compatibility

- No new, changed or removed settings.
- MCP surface: no tool, schema or field changes. `serverInfo.version` reports `1.31.0`.
- No dependency changes.

## Deployment and rollback

No migration. Install the release binary as usual. No CT222 change, because the preview renderer is
unchanged.

Rollback: the v1.30.0 and v1.30.1 binaries start on data written by this release (schema 40).

## Verification

  doctests, strict `cargo doc`, `cargo deny check`, the image build and the browser suites.
- Locally through `cargo-sandboxed`: 1,303 root tests (including the conformance replay, the MCP
  surface check and the layering test) and the 42/42 historical fixtures.

  - 9,909 replayed reads with identical status histograms.
  - Every difference was expected: the version string, the v1.30.1 `collections.css` rule, and one
    relative time that crossed an hour boundary.
  - The write phase and 33 admin steps matched.
  - Restart, backup, rollback to v1.30.0 and boot from backup all succeeded.
